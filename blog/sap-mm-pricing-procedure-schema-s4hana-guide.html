SAP MM Pricing Procedure (Calculation Schema) Configuration Guide for S/4HANA

Configure the SAP MM pricing procedure end to end: field catalog, condition tables, access sequences, condition types, calculation schema and schema determination, with errors and interview questions.

Purchase order prices in SAP do not come from a single field. They are calculated by the condition technique, driven by a calculation schema (the MM name for a pricing procedure). When a PO shows the wrong net price, a freight condition is missing, or a discount is not picked up, the cause nearly always sits somewhere in this chain.

This guide walks through the SAP MM pricing procedure configuration in the order you would build it: field catalog, condition tables, access sequences, condition types, the calculation schema, and schema determination. You will also see how to test it, which errors to expect, and how interviewers ask about it. The menu paths are the same in ECC and S/4HANA, and I flag the differences where they exist.

⚡ Key takeaways
  • MM pricing uses the same condition technique as SD: field catalog, condition tables, access sequences, condition types, calculation schema and condition records.
  • The standard schema is RM0000 and gross price is PB00; always copy to Z objects instead of changing standard ones.
  • The schema is found by combining the purchasing organization schema group, the vendor schema group and optionally a document schema group.
  • Use the Analysis button on the PO condition screen to find out why a price is missing.
  • Account keys and accruals in the schema link pricing to FI postings through OBYC.
  • Changing a schema does not reprice existing POs; update pricing or create new documents.
Process at a glance
  1. 1Field catalog & tablesCreate condition tables with M/03 using fields from the catalog.
  2. 2Access sequence (M/07)Order tables from most specific to most general.
  3. 3Condition types (M/06)Copy standard types and link the access sequence.
  4. 4Calculation schema (M/08)Add steps, From/To, subtotals and account keys.
  5. 5Schema determinationAssign vendor, purchasing org and document groups to the schema.
  6. 6Test in ME21NCreate condition records and check the PO Conditions tab.

01How condition technique works in MM purchasing

Condition technique is the mechanism SAP uses to find prices, discounts, surcharges, freight and taxes automatically. In MM it is used in purchasing documents (info records, contracts, scheduling agreements, POs) and also in output determination and some other areas.

The building blocks are chained together like this:

  1. Field catalog: the list of fields that may be used in condition tables.
  2. Condition table: a key combination of fields, for example Vendor + Material.
  3. Access sequence: an ordered list of condition tables searched for a valid record.
  4. Condition type: represents a price element (gross price, discount, freight) and points to an access sequence.
  5. Calculation schema: the ordered list of condition types with calculation logic.
  6. Schema determination: assigns the schema to the document based on purchasing org, vendor schema group and (optionally) document schema.

Condition records (maintained in MEK1, MEK1 for conditions with validity, or inside info records via ME11 / ME12) hold the actual values. Without a record, the access sequence finds nothing and the condition stays empty.

MM vs SD: The concept is identical to SD pricing, but MM uses application M and usage A, with condition types starting with P (for example PB00) and schemas starting with RM. If you know SD, see our SAP SD pricing procedure guide for the sales-side comparison.

03Step 1: Field catalog, condition tables and access sequences

The SPRO path is SPRO → Materials Management → Purchasing → Conditions → Define Price Determination Process. Everything in this section lives under that node.

Maintain condition tables

  1. Open Maintain Condition Tables (M/03 to create, M/04 change, M/05 display).
  2. Choose a number in the customer range (501 and above).
  3. Select fields from the field catalog, for example Vendor, Material, Plant.
  4. Generate. SAP creates a physical table named A + number (for example A501).

If a field is missing, add it to the field catalog first in Maintain Field Catalog. Fields must exist in structure KOMG (the communication structure) or be added by an enhancement.

Maintain access sequence

  1. Open Define Access Sequences (M/07).
  2. Create a sequence such as ZPB0.
  3. Under Accesses add tables in priority order: specific first, general last.
  4. Per access, check the Exclusive flag and map fields under Fields.
Access no.TableKeyPurpose
10Standard A017 styleVendor / Material / Plant / Info rec. categoryPlant-specific price
20Standard A018 styleVendor / Material / Info rec. categoryClient-wide price
30Custom A501Vendor / Material groupFallback discount

Table numbers above are examples of the standard pattern; check your system for the exact numbers.

If the access is marked Exclusive and finds a record, SAP stops searching even if a later access has a better price. Mis-ticking this is a classic cause of unexpected prices.

For a delivery cost (freight) that should be planned and then invoiced via MIRO, tick the delivery costs category and set the condition so that it is accrued at goods receipt. Without this, freight posts at invoice only.

Also set Group condition, Rounding rule, and the validity default. Use condition categories carefully, because they change posting behaviour in valuation, not just pricing.

05Step 3: Building the calculation schema

Path: SPRO → Materials Management → Purchasing → Conditions → Define Price Determination Process → Define Calculation Schema (M/08). Copy RM0000 to ZM0000, then open Control.

Each line is a step in the calculation. The important columns:

SubtotalStores amount in a field (for example, to be used in a later formula)

Account key / AccrualsPosting key for FI/MM, used with OBYC

Worked example

A client buys steel rods. Gross price is ₹100 per kg for 1,000 kg. The vendor gives a 5% discount and charges ₹2,000 freight, and 18% GST applies.

Note that tax in India is handled through the tax procedure (TAXINN), not the main MM schema, so GST conditions are calculated from the base you define in the tax procedure. Treat the last row as an illustration of the base.

"What is the difference between a subtotal and a statistical condition?" A subtotal only stores an intermediate value for later steps; a statistical condition is displayed but excluded from the net price and from posting.

06Step 4: Schema determination

The schema must be found automatically on the PO. Configuration is under SPRO → Materials Management → Purchasing → Conditions → Define Price Determination Process → Define Schema Determination.

  1. Define schema group, vendor (OLMEKV style path): create a group such as Z1.
  2. Assign the group to the vendor in the vendor master, Purchasing data (XK02 in ECC, BP in S/4HANA), field Schema Group, Vendor.
  3. Define schema group, purchasing organization and assign it to the purchasing organization.
  4. Define the schema group for the document only if you need to vary the schema by document type. Assign the schema group to the document type (for example NB) in OMET style document settings.
  5. Assign schema to the combination using Calculation Schema → Schema Determination → Determine the Schema: purchasing org schema group + vendor schema group (+ document schema).
Purch. org schema grpVendor schema grpSchema
01Z1 (domestic)ZM0000
01Z2 (import)ZMIMP
S/4HANA: The vendor is a Business Partner, so the schema group field is maintained in BP under the vendor purchasing role. Customizing paths remain unchanged.

Schema determination in the purchase order cycle works together with the rest of procurement; see how to configure a complete PO cycle for the surrounding steps.

07Testing, freight, discounts and the Fiori experience

Creating condition records

Use MEK1 (create), MEK2 (change), MEK3 (display) for conditions with validity periods. In S/4HANA, the Fiori app Manage Purchasing Info Records and the Manage Purchase Contracts app also maintain conditions, though condition types and access sequences are still configured in SPRO.

Test procedure

  1. Create a vendor with schema group Z1.
  2. Maintain a PB00 record in MEK1 or info record ME11 for the material.
  3. Create a PO in ME21N (or Fiori Manage Purchase Orders).
  4. In the item, open the Conditions tab and check that the gross price, discount and freight lines appear.
  5. Use the analysis function (Analysis button on the condition screen) to see which access found a record, or why none did.
The Analysis button is the fastest debugging tool. It lists every access, its table, and the result for each condition type, so you can see the exact missing key.

Posting impact

Condition types feeding delivery costs or price differences post through account keys, such as FRE (freight) and FR1. These use OBYC. For details, see our OBYC masterclass.

09Interview questions on this topic

  1. What are the components of condition technique? Field catalog, condition tables, access sequences, condition types, calculation schema and condition records.
  2. How does SAP find the schema in a PO? Through the vendor schema group, the purchasing org schema group and, optionally, the document schema group.
  3. What does the Exclusive indicator do? It stops the access sequence at the first successful access.
  4. Where do you maintain a condition record with validity? MEK1, or in the info record or contract.
  5. How do you add a new freight condition? Copy FRB1, assign the access sequence, add to the schema, and set account keys.
Interviewers often give a scenario: "A PO has no price even though info record exists." Walk through schema determination, the access sequence, validity, and the Analysis function. More such questions are in our Top 30 SAP MM interview questions.

?Frequently asked questions

What is the calculation schema in SAP MM?

It is the MM equivalent of the SD pricing procedure. It is an ordered list of condition types with rules for base, subtotals, account keys and accruals, and it determines how the net price of a purchase order item is calculated. The standard schema is RM0000.

Which T-code is used to define the calculation schema in MM?

Use M/08 or the SPRO path Materials Management > Purchasing > Conditions > Define Price Determination Process > Define Calculation Schema. Related codes include M/06 for condition types and M/07 for access sequences.

How does SAP determine the pricing schema in a purchase order?

Through schema determination, which combines the purchasing organization's schema group, the vendor's schema group and, optionally, the document's schema group. The combination is assigned to a calculation schema in customizing.

Why is my PO price zero even though a condition record exists?

Common reasons are an expired validity date, a vendor in a different schema group, a condition type missing from the schema, or an access sequence that does not match the record's key. Use the Analysis function on the condition screen to see the exact result.

Where do I maintain condition records in purchasing?

Use MEK1, MEK2 and MEK3 to create, change and display conditions, or maintain them directly in purchasing info records (ME11/ME12) and contracts. In S/4HANA, Fiori apps are also available.

Is MM pricing different in S/4HANA?

The condition technique and customizing paths remain the same. The main differences are that vendors are maintained as Business Partners and that many users work in Fiori apps instead of classic GUI transactions.
