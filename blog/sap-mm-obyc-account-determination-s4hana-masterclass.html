SAP MM OBYC Account Determination: S/4HANA Automatic Posting Masterclass

How OBYC automatic account determination works in S/4HANA: valuation class, transaction keys BSX, WRX, GBB, PRD, modifiers, configuration steps, errors and interview questions.

Updated Nov 14, 2026

T-codes covered

OBYCOMS2MM01MM02MR21OMJJFS00MIGO

Every goods movement and invoice receipt in SAP MM creates an accounting document, and nobody types the G/L accounts. The system picks them through SAP MM OBYC account determination. When it is configured wrongly, you see "Account determination for entry XYZ 3000 BSX not possible" in production at month-end, and the whole warehouse stops posting.

This guide shows how the logic works end to end: material master to valuation class, then transaction key, modifier and G/L account. You will learn the main keys (BSX, WRX, GBB, PRD, UMB, KDM), how to configure them in OBYC, how to trace a posting, and how to fix the usual errors. It also covers what changed in S/4HANA and the questions interviewers ask.

⚡ Key takeaways
  • OBYC finds the G/L account from chart of accounts, transaction key, valuation class and, for some keys, a modifier or valuation grouping code.
  • BSX is the stock account, WRX is GR/IR, GBB is the offset for consumption and scrap, and PRD/UMB handle price differences and revaluation.
  • GBB needs a general modification such as VBR, VNG, BSA, INV or AUF, which comes from the movement type's posting string.
  • Keep valuation classes few and aligned to inventory account types, because each class multiplies OBYC entries.
  • Test with OMWB before transport and trace live postings through the transaction key in the FI line item.
  • In S/4HANA the postings land in ACDOCA, and cost-relevant expense accounts must exist as primary cost elements.

01How OBYC account determination works

OBYC (Configuration of Automatic Postings – Inventory Management) is the table-driven bridge between Materials Management and Financial Accounting. The system does not look at the material for a G/L account. It builds a lookup key from several attributes and finds the account in a customizing table.

The lookup chain for a goods movement is:

  1. The movement type (for example 101, 261, 301) determines the transaction/event key through the table T156 and the posting string logic (T156S, value string).
  2. The material's valuation class (field in the Accounting 1 view, table MBEW-BKLAS) is mapped through the valuation grouping code and the chart of accounts (OMSK).
  3. Where needed, the general modification (account modifier) is added, such as the value from the movement type's account grouping.
  4. The chart of accounts, via the valuation area's company code, selects the G/L account in T030.

So the effective key is: chart of accounts + transaction key + (valuation grouping code) + (modifier) + valuation class = G/L account. Not every key uses all dimensions, which is why each key's configuration screen looks different.

ECC vs S/4HANA: The OBYC logic is the same, but in S/4HANA the postings flow into the Universal Journal table ACDOCA, and the material ledger is mandatory. See our Universal Journal guide. Also, the material master field is still valuation class, but the material number length can be 40 characters.

02Material type, valuation class and account category reference

The valuation class is the most important link. It is not defined on the material type directly. It is assigned in the material master (Accounting 1) and restricted by the account category reference on the material type's valuation setup.

StepPath / T-codeWhat you do
1SPRO > Materials Management > Valuation and Account Assignment > Account Determination > Account Determination Without Wizard > Define Valuation Classes (OMSK)Create account category reference (e.g. 0001 Raw/Trading) and valuation classes (3000 Raw Materials, 7900 Semi-finished, 7920 Finished goods)
2Same node, Define Account Category ReferenceLink which valuation classes are allowed for an account category reference
3Material type (OMS2)Assign the account category reference to the material type
4MM01/MM02 Accounting 1User selects a valuation class from the allowed list

The standard design practice is to keep valuation classes aligned to the type of inventory account: raw materials, packaging, semi-finished, finished goods, trading goods, spares. Do not create one class per material, because every class multiplies the OBYC entries you must maintain. Our material master views guide covers the Accounting view fields.

Warning: Changing the valuation class on a material that has stock is restricted. In S/4HANA you need the stock to be zero or use the revaluation approach. Plan the class design before go-live, because correction later means a lot of postings.

03Key transaction keys: BSX, WRX, GBB, PRD, UMB, KDM

You will meet these keys in every implementation. Learn what each one posts, and which dimensions it needs.

Keep in mind: BSX is the debit side of a goods receipt (101) into stock, while WRX is the credit side to GR/IR. For a goods issue to a cost center (201), GBB with modifier VBR is the debit to expense and BSX the credit to stock.

Tip: To see which keys a movement type uses, go to OMWB (Simulation of automatic postings), enter a movement type and valuation class, and the system displays the debit and credit accounts without a real posting.

04General modification: BSA, VBR, VNG, and others for GBB

The GBB key is used by many movement types, so the system adds an account modifier (general modification) to separate them. It comes from the movement type's reference in T156/T156S and is visible in OMJJ (Customizing: new movement types) under the posting string reference and account grouping.

ModifierUsed forExample movement types
BSAInitial entry of stock balances561
VBRConsumption posting for internal goods issue (cost center)201, 202
VNGScrapping / loss in goods receipt551, 552
AUFGoods receipt for production order offset101 against order, 261
INVInventory difference (physical inventory)701, 702
VAX/VAYDelivery-related consumption (sales order)601
ZOBGoods receipt without PO501

For a worked example, say plant 1000, chart YCOA, valuation class 3000. A 201 issue of 10 pieces at standard price INR 500 posts: Debit 400000 (Consumption – raw material, from GBB/VBR/3000) INR 5,000; Credit 300000 (Raw material stock, from BSX/3000) INR 5,000. The cost center is the account assignment in the movement.

If the finance team wants different expense accounts per department, you can use the same modifier but different valuation classes, or create a custom movement type with a different account grouping in OMJJ. Do not hard-code business logic in a user exit when OBYC can handle it.

Note: In S/4HANA, expense accounts for cost-relevant postings must be cost elements (primary cost elements are G/L accounts of type "Primary costs or revenue"). A missing cost element master gives an error when posting to a cost center.

05Step-by-step configuration of a new valuation class in OBYC

Assume the business adds a new class 3050 "Packaging Material". Here is the procedure.

  1. Create the G/L accounts in FS00 (stock account 300050, consumption account 400050) with the chart of accounts and company code segments. Stock accounts must allow automatic postings only ("Post automatically only") and be reconciliation-neutral for MM.
  2. In OMSK, create valuation class 3050 and add it to the account category reference used by material type packaging (for example VERP).
  3. Run OBYC, select the chart of accounts, and open BSX. Add valuation grouping code (if used) and class 3050, with account 300050.
  4. Open GBB. For each general modification relevant to you (VBR, VNG, INV, AUF) add 3050 with the right expense account.
  5. Maintain WRX (GR/IR), PRD or UMB as the material's price control requires, and BSV/KDM if used.
  6. Test with OMWB, then post MIGO 101 and 201 documents and check MB03 and FB03.
  7. Transport the customizing request. Note OBYC entries are cross-client customizing in T030 keyed by chart, so make sure the request is client-independent where appropriate.
Tip: Use the "Account Determination with Wizard" only to review the logic. In real projects the consultants usually maintain in OBYC directly, because it is faster and easy to export for audit.

06Tracing a posting and linking to invoice verification

When finance asks "why did this go to account X?", follow this sequence.

  1. Open the material document in MB03 and click the accounting document.
  2. In FB03 / FAGLL03, double-click the line item and check the "Transaction key" field (field KTOSL, e.g. BSX).
  3. Check the valuation class on the material (MM03 Accounting 1).
  4. Run OMWB with the same movement type, plant and class and compare.

For the purchasing cycle, a standard-price material posts at goods receipt: Dr BSX stock at standard price, Cr WRX GR/IR at PO price, and the difference to PRD. At invoice receipt (MIRO) the system debits GR/IR (WRX), credits the vendor reconciliation account, and posts further differences to PRD or to stock for moving average. See the purchase order cycle guide for the whole flow.

If the material is valued with actual costing, PRD and UMB are replaced by material ledger logic and the price differences are collected in the ML. The material ledger guide covers this. For split-valuated stock, each valuation type can have its own class, so be sure to read the split valuation article too.

Warning: Never solve an error by pointing every class to a single suspense account. It passes the test but ruins inventory reconciliation, and the month-end difference between MM and FI becomes impossible to explain.

08Common mistakes and good practice

  • Too many valuation classes. Each one needs entries for BSX, GBB (multiple modifiers), PRD/UMB and more. Design around account needs.
  • Skipping OMWB tests. Always simulate before transport.
  • Ignoring valuation grouping codes. If plants have different accounts, check OMWD (valuation grouping) before assuming one setting works for all.
  • Forgetting new custom movement types. A copied movement type in OMJJ keeps the same posting string; change it only if you intend different accounts.
  • Not aligning with FI. The FI lead should approve the account list, including reconciliation account flags and cost element categories.

Practising on an S/4HANA sandbox, where you can create a class, post a 101 and 201 and inspect the line items, teaches this faster than reading. If you are building your MM skills in order, this 3-month plan places OBYC in the right sequence.

09Interview questions on this topic

Q: How does the system determine the G/L account for a goods receipt? Answer in sequence: movement type → transaction key (BSX/WRX) → valuation class from the material → chart of accounts → account in T030.
  • What is the difference between BSX and GBB? (BSX is the stock account; GBB is the offset such as consumption, with a general modification.)
  • Which key holds GR/IR? (WRX.)
  • How would you give two plants different stock accounts? (Valuation grouping code via OMWD and OBYC entries by grouping.)
  • A 201 posting fails with a GBB/VBR error. What do you check? (OBYC for GBB, modifier VBR and the valuation class.)
  • How do you test without posting? (OMWB.)

?Frequently asked questions

What is OBYC in SAP MM?

OBYC is the transaction for configuring automatic postings in Inventory Management and Invoice Verification. It maps transaction keys such as BSX, WRX and GBB to G/L accounts per chart of accounts and valuation class.

What is the difference between valuation class and valuation grouping code?

The valuation class comes from the material master and groups materials by the type of stock account. The valuation grouping code groups valuation areas (plants) so that different plants can use different accounts for the same class.

How do I find which account a movement type will post to?

Use OMWB, enter the movement type, plant and valuation class, and the system simulates the debit and credit accounts. For posted documents, check the transaction key on the FI line item.

Why do I get 'Account determination for entry BSX not possible'?

No G/L account is maintained for that chart of accounts, transaction key and valuation class combination. Add the entry in OBYC for the valuation class stated in the message and retest.

Did OBYC change in S/4HANA?

The configuration logic is unchanged. The differences are that postings are stored in the Universal Journal ACDOCA, the material ledger is always active, and cost elements are G/L accounts.

Is OBYC used for SD postings?

Not for revenue. Sales revenue and COGS postings use VKOA for revenue accounts and OBYC key GBB with modifier VAX/VAY for COGS on delivery related goods issue.

Can I change the valuation class of a material with stock?

It is restricted and needs care. Normally you move stock to zero or use a controlled process with FI approval, because the change shifts value between G/L accounts.
